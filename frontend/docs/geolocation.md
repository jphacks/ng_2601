# 現在地表示（GPS）の仕様と制約

[Issue #14（FE-12）](https://github.com/jphacks/ng_2601/issues/14)の実装メモです。実装は[`src/features/geolocation/`](../src/features/geolocation/)、地図側の受け口は`MapController.setCurrentLocation`（[`map.ts`](../src/features/map/map.ts)）です。

## 動作

- 地図右の現在地ボタンを**押したときだけ**、ブラウザーのGeolocation APIで位置を1回取得する。ページ読み込み時の自動取得・追跡（`watchPosition`）はしない。走行中の追跡・ナビは将来機能。
- 取得できたら現在地マーカー（青い点。タップで精度を表示）を置き、現在より引いた表示にならない範囲で現在地へ地図を移動する。精度が約500mより粗いとき（IPベースなど）は寄り過ぎない。
- 検索パネルは取得開始時に閉じる（通知と現在地が隠れないため）。地点指定モード中でも使え、指定は続く。

## 状態と表示

| 状態 | 原因 | 表示・操作 |
| --- | --- | --- |
| 許可待ち／取得中 | 許可確認の表示中、または測位中 | 「現在地を取得しています…」と「キャンセル」。ボタンは`aria-busy`。キャンセル後に届いた応答は捨てる |
| 成功 | 取得できた | マーカーと「現在地を表示しました（精度 約N m）」（5秒で消える） |
| 拒否 | 利用者または端末が許可していない（`PERMISSION_DENIED`） | 設定で許可する案内と「再試行」「閉じる」。地図の閲覧と地点指定は使える旨を明記 |
| タイムアウト | 15秒以内に取得できない | 再試行を案内 |
| 取得不可 | 端末の位置情報サービスOFF・測位不能（`POSITION_UNAVAILABLE`）、APIの呼び出し例外 | 位置情報サービスの確認を案内 |
| 非対応 | `navigator.geolocation`がない | 地点指定を案内（再試行なし） |
| 非セキュア | HTTPSでもlocalhostでもない（`isSecureContext`が偽） | HTTPSが必要と案内（再試行なし） |

失敗の通知は地図とメニューボタンを覆わない位置に出し、地図の操作と地点の手動指定は常に使える。

## プライバシー

- 取得した位置は画面表示（マーカー・地図移動）にだけ使う。サーバーへの送信、`localStorage`等への保存、`console`出力はしない。経路検索へ出発地として自動入力もしない（出発地・目的地は利用者が地図で指定する）。
- ブラウザーのGeolocationは利用者の許可が前提で、許可状態の管理はブラウザーが行う。

## HTTPSと端末権限の制約

- Geolocation APIは**セキュアコンテキスト**（HTTPS、または`localhost`/`127.0.0.1`）でのみ使える。本番やスマホ実機の確認ではHTTPSで配信すること。LAN内のIPアドレスをHTTPで開くと、ブラウザーが拒否する。
- 許可を一度「ブロック」すると、ページからは再度確認を出せない。利用者がブラウザーのサイト設定（アドレスバーの鍵／設定アイコン）で許可を戻す必要がある。
- スマホでは、OSの位置情報サービスと、ブラウザーアプリへの位置情報の許可の両方が必要。iOSでは「設定 > プライバシー > 位置情報サービス」、Androidでは位置情報のON。
- 埋め込み（iframe）では`Permissions-Policy: geolocation`が許可されていないと使えない。
- ブラウザーによっては許可確認を選ばずに閉じてもエラーが返らない。そのため取得中の通知に「キャンセル」を置いている。
- 屋内・都市部などでは精度が低い、または測位に時間がかかる。精度は通知とマーカーで表示する。

## 検証メモ

実際のGeolocationの許可・拒否はブラウザーの権限UIで決まるため、開発時の確認では`navigator.geolocation.getCurrentPosition`を差し替えて各状態を再現した（実端末のGPSでの確認は未実施）。
