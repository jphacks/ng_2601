# CyclerHub（さいくらーはぶ）

[日本語](README.md) | [English](README.en.md)

自転車の種類、走りたい道、周囲の道路情報を踏まえてルートを探すサービスです。

## 製品概要

### 背景（製品開発のきっかけ、課題等）

自転車は身近な移動手段ですが、坂道や舗装、交通量、通行規制によって走りやすさが大きく変わります。[国土交通省の資料](https://www.mlit.go.jp/toshi/content/001880113.pdf)では、自転車の交通手段分担率の長期的な低下が示されています。2026年4月には[16歳以上の自転車利用者に青切符が適用](https://www.npa.go.jp/bureau/traffic/bicycle/info.html)され、交通ルールを把握して走ることも一層大切になりました。CyclerHub は、道路環境への不安から自転車を使いづらい人が、自分に合う経路を選べるようにすることを目指します。

### 製品説明（具体的な製品の説明）

出発地と目的地、自転車の種類、坂道・交通量・路面・押し歩きの希望を指定して経路を検索します。バックエンドは [BRouter](https://github.com/abrensch/brouter) を用いて候補経路を探索し、利用可能な道路規制情報の範囲で通行できない候補を除外し、希望に応じて候補を比較して経路を返します。
さらに、事故履歴、ユーザー投稿、機器による路面計測を、経路周辺の参考情報として表示します。これらを将来の経路選択にも生かせるよう、異なる情報源をつなぐ基盤を構築しています。

### 特長

#### 1. 複数の情報を生かす自転車ルート探索

シティサイクル、電動アシスト、ロードバイク、グラベルバイク、ママチャリの5種類に対応。車体特性と坂道・交通量・路面・押し歩きの希望から BRouter が候補を作り、バックエンドが道路規制と、十分な範囲をカバーする交通量データを踏まえて経路を選びます。**統合済み。**

#### 2. 走る道を見て選べる地図

地図上の経路に、国土地理院の標高データから推定した標高グラフ・勾配表示を連動。事故履歴、交通量、利用者の投稿を情報源ごとに見られます。**統合済み。**

#### 3. 走行データで育つ道路情報

M5Stack CoreS3 と GPS で段差・振動の候補を取得し、Wi-Fi で送信・表示する仕組みを実装。**実装・実機でのデータ取得を確認済み。** 経路選択への活用は今後の展望です。

### 解決出来ること

同じ距離でも、走りやすさは自転車や人によって異なります。CyclerHub は車体と走り方に合う候補を、道路規制・交通量・坂道・路面の情報とともに示し、自転車に乗りたい人が経路を選びやすくします。

### 実装・検証済み：CoreS3 による路面計測

M5Stack CoreS3 の加速度センサーと GPS で段差・振動の候補を記録し、Wi-Fi で送信して地図に表示します。実機でのデータ取得を確認済みです。検出精度と実走行での評価を進め、経路選択への活用を目指します。詳細は[seamsドキュメント](seams/README.md)をご覧ください。

### ログイン・認証

Google アカウントでログインする画面を実装しました。ログイン後は認証が必要な口コミ投稿や設定の保存に進めます。アクセストークンの期限切れ時の更新とログアウトにも対応しています。メールのリンクによる認証はバックエンドに実装されており、画面との接続を進めています。

### 今後の展望

事故履歴、ユーザー投稿、実走行で得た路面データの信頼性と使い方を検証し、経路探索へ段階的に反映することを目指します。CoreS3 の実走行検証と検出精度の評価も進めます。

設定の保存画面と API、地点・経路を保存するバックエンド API は実装済みです。今後は地点・経路の保存画面と連携を整え、日常的に使う条件やルートを継続して利用できる体験に発展させます。

### 注力したこと（こだわり等）

- **自転車を一種類として扱わない設計**：5種類の車体に異なるパラメータを設定し、利用者の希望を経路探索に反映しました。
- **情報源の役割を分けた経路選択**：道路規制は候補の通行可否、交通量は条件に応じた候補選択、事故履歴や投稿は参考情報として扱います。
- **現実の路面情報への拡張**：CoreS3 の計測データを取得・送信・表示できる仕組みを作り、次の経路評価につなげます。
- **少ない操作で使える経路探索** : 現在地を起点に、地図上の地点を選ぶだけで経路を探せるようにし、直感的に操作しやすくしました。
- **坂道を直感的に把握できる表示** : 標高グラフと地図表示を連動させ、上り・下りの区間や急な坂の位置を視覚的に理解しやすくしました。
- **必要な情報に集中できるUI設計** : 地図上の不要な表示を減らし、詳細な検索条件は必要なときだけ展開できるようにすることで、情報の見やすさと操作のしやすさを両立しました。UIの形と期待される操作が一致するようにUIを設計しました。

## 開発技術

### 活用した技術

#### API・データ

- OpenStreetMap (BRouterの内部で利用)
- 国土地理院の標高データ
- JARTIC の交通規制
- 警察庁の事故履歴
- 道路交通量

情報源ごとの役割は[外部データ利用ドキュメント](back/docs/external-data.md)に記載しています。

#### フレームワーク・ライブラリ・モジュール・デバイス

- フロントエンド：TypeScript、Vite、MapLibre GL JS
- バックエンド：Python、FastAPI、PostgreSQL/PostGIS、BRouter
- 環境 ：docker、uv(開発環境)、PlatformIO
- ハードウェア：M5Stack CoreS3、GPS ユニット

### 独自技術

#### ハッカソンで開発した独自機能・技術

- 自転車別の[経路設定](back/config/routing_catalog.json)と[BRouter プロファイル](back/brouter_extension/profiles/japan_bicycle.brf)を構築しました。
- [経路 API](back/backend/app/main.py)で、BRouter の候補に道路規制・交通量を組み合わせて経路を選びます。
- CoreS3 の[計測・送信プログラム](seams/M5StackS3/src/main.cpp)と[受信 API](back/backend/app/device_events.py)を実装しました。
