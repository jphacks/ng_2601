# 重要な意思決定（ADR）

技術選定、責務境界、APIの互換性など、後から理由を知る必要がある重要な設計変更だけを記録します。通常の実装判断はPR本文で十分です。確認できない過去の判断を後付けで作りません。この導入では過去のADRを新設しません。

ファイル名は`YYYY-MM-DD-short-topic.md`とします。同日に同名を作らないよう関連PRで調整してください。下記を必要なときにコピーして使います。

```markdown
# 判断の題名

- 状態: 提案 / 採用 / 却下 / 廃止（後継ADRへのリンク）
- 日付: YYYY-MM-DD
- 関連Issue / PR:
- 決定者・合意の根拠:

## 背景・解決する問題

## 検討した選択肢

## 決定と採用理由

## 制約・影響・トレードオフ

## 参照・後継の判断
```

提案は採用と区別し、チームの合意とPRのマージ状態が分かる根拠を残します。採用後に変更する場合は後継ADRを作り、元の理由を消さずに状態と参照を更新します。現在の仕様は[architecture.md](../architecture.md)と[API契約](../api-contract.md)にも反映し、ADRだけから現状を推測させないでください。
