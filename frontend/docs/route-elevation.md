# ルート標高解析（Issue #7 / FE-05）

検索した1本のルートを先に表示し、標高解析を非同期で追加する。距離・所要時間は経路API、標高関連の値はDEM解析に由来する。BEが持つ獲得標高や最大勾配をDEMの数値と混在させない。外部APIの構造・`Route`型は変更していない。

## データと計算

- 実装は[`src/features/elevation/`](../src/features/elevation/)。取得・復号・補間・解析の移植元は[`norinori1/poc-maplibre` の `9efa773`](https://github.com/norinori1/poc-maplibre/tree/9efa773ef69588407361f0d19ea4b65bb67d26ae/src)。UIは経路ビューのルート結果に統合した。
- 実通信は国土地理院DEM5A PNG（z15）を優先し、404・欠測だけDEM10B PNG（z14）へ切り替える。通信・HTTP・復号エラーでは切り替えない。RGBは色空間変換・拡縮なしで復号し、透明・半透明画素と欠測RGBを除外する。画素中心で双線形補間し、4画素が揃わない場合だけ中心画素へ戻る。
- 同時取得・復号は6件。取得は20秒でタイムアウト。共有中リクエストとLRUキャッシュを使い、復号済み配列は32MiB・128件まで。404は60秒保持、エラーは保存しない。永続保存・タイルの再配信は行わない。
- 経路座標から大円距離を累積して、20m間隔・最大400点で始終点を含めて採取する。長い経路は間隔を広げる。APIの走行距離とグラフ距離は計算元が異なり、差があり得る。
- 獲得標高・下降量は起点から1m以上の変化を集計するPoCの方式。平滑化は行わない。全体平均勾配は `(終点標高−始点標高) / 経路座標の累積距離 × 100`。5m未満や標高欠測時は計算しない。
- 最大上り・下りは同じ連続有効区間内の100m窓で求める。100m先の標高は同区間内だけで補間する。100m区間がなければ不明。該当方向がなければ0%。瞬間的な道路勾配ではない。

## 表示と欠測

- 表示は距離・時間・獲得標高・最大上りの4つと標高グラフだけにする。走る人の判断に使わない値（下降量、全体平均勾配、最低・最高標高、最大下り）や計算方法の説明は画面に出さない。候補リスト・順位・選択ボタンは設置しない。
- 距離は整数m／小数2桁km、標高・上下量・勾配は小数1桁、時間は分単位。丸めで1000mになる距離はkm表示へ揃える。負の標高と真の0は有効値。欠測は「不明」と区別する。
- グラフは横軸が距離、縦軸が標高。平坦でも縦軸幅は10m以上。欠測区間は線を切り、孤立した有効点は点で示す。
- 部分欠測では集計を分割し、「一部の地点で標高を取得できませんでした。」と表示する。全体平均勾配は不明。全欠測や連続有効区間のない場合、上下量を0と表示しない。
- 経路検索と標高解析は独立した状態を持つ。解析失敗でも経路を残し、解析だけ再試行できる。再検索・リセットでは旧解析の待機と次バッチを止め、遅れた進捗・成功・失敗を破棄する。共有取得そのものは他の利用者のために継続する。
- 条件の編集だけでは解析を変更せず、適用済み条件と変更通知を維持する。勾配色分けとグラフ・地図のポインタ連動は、同じ解析結果を使う独立表示として実装している。

## 地図の勾配色分け（Issue #8）

`RouteAnalysis.summary.windows[100]`が持つ100m DEM勾配窓を地図表示に再利用する。`Route`型や検索APIには区間勾配を追加しない。表示区間の形状は元の経路座標から同じ累積距離で切り出すため、解析用サンプル点だけで道路形状を近似しない。

- 正の勾配は上り、負は下り、0%は平坦として凡例と色で示す。線幅も勾配の絶対値に連動し、10%以上で表示上の幅を飽和させる。これは表示上のスケールであり、危険度・通行可否を示す閾値ではない。
- 欠測、またはその場所を含む有効な連続100m窓がない区間は灰色の破線とし、0%や安全な区間として扱わない。100m窓は#7と同じ有効区間内だけから選ぶ。
- 地図上の区間を選ぶと、その表示距離、色の根拠にした100m計測窓、符号付き勾配を数値表示する。色・線幅に加え、凡例と選択結果の文字・数値で確認できる。
- Issue #8に記載されたバックエンドとの勾配閾値合意は未確認。FE-06ではAPIの閾値を推測して導入せず、DEM由来の勾配符号と#7の100m窓だけを使用する。

## 地図とグラフの連動（Issue #9）

標高プロファイル上の位置と地図上のルート位置・区間を双方向に連動させる。選択位置は「経路に沿った累積距離(m)」1つで表し、[`selection.ts`](../src/features/elevation/selection.ts)が距離と経路座標・推定標高・勾配区間を対応付ける。[`link.ts`](../src/features/elevation/link.ts)がグラフと地図の唯一の選択状態を持ち、どちらの操作も `select(distanceM)` に集約する。経路・解析が変わったときだけ選択を解除・再対応付けし、同じルートの再描画では位置を保つ。

- グラフのホバー／タップで、地図に選択位置の丸印と、勾配の根拠になった100m計測窓の帯を表示する。帯はルート線の下に敷き、#8の勾配色を隠さない。
- 地図のルート区間をタップすると、クリック座標を区間の折れ線へ投影して経路距離に戻し、グラフの縦線・スライダー・数値表示を同じ位置へ移動する。地図に出す区間の文言は#8と共通にする。
- グラフの下に「位置／標高／勾配（100m窓）」を文字と数値で表示する。色だけに依存しない。欠測は「不明（欠測）」と表示し、0m・0%に置き換えない。未知区間は連動する勾配区間がない場合も「不明」とし、対応する100m窓がない勾配は作らない。
- キーボードはグラフ下のスライダーで操作する（←→で10m、PageUp/PageDownでページ移動、Home/Endで始終点）。スライダーには説明文とラベルを関連付ける。タッチはグラフのタップ（10px以上の移動はスクロールとして扱う）と地図の区間タップで同じ位置を選べる。
- 高頻度イベント対策として、グラフの `pointermove` は `requestAnimationFrame` で1フレーム1回にまとめ、SVG全体を作り直さない。地図は選択位置のマーカー移動だけを行い、ハイライト帯の `setFilter` は100m窓が変わったときだけ呼ぶ。勾配区間の生成は解析完了時だけ行う。
- 連動の対象は、#7の解析点が1点以上ありグラフを表示できる場合に限る。全欠測ではグラフ自体を表示しない（#7の規則）。
- 検索カード（`.search-card`）は全幅の箱を持つため、そのままだと地図のクリックがカードに吸われて区間を選べない。バー・パネルの外側は地図へ操作を通すよう[`shell.css`](../src/features/shell/shell.css)を最小修正した。カード表示中の地図クリックは従来どおりカードを閉じ、同時に地点・区間の操作が届く。
- 確認はViteモックで行う。PC 1280×800と375×812で、グラフのホバー／タップ／キーボード、地図の区間タップ、`?elevation=hill|partial|flat` の数値、選択位置を保った再描画を確認した。実GSI DEMの連動、実BE結合、実機モバイル、Safari／Firefox、スクリーンリーダーは未検証。

## 出典と推定値の注記

標高タイルのリアルタイム利用は、[国土地理院の公式案内](https://maps.gsi.go.jp/development/ichiran.html)に基づき、出典明示で申請不要と判断している（2026-10-25確認）。[利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html)に沿って、出典は地図右下の帰属表示「地理院タイル（標高タイルを加工して利用）」にまとめ、結果欄には注記を出さない。地表面の推定値であり、橋・トンネル等の路面高と一致しない場合がある。

## 開発・確認

`VITE_API_MODE=mock`（既定）では同じ解析処理に合成標高を渡し、DEMへの通信は行わない。URLの`elevation`指定はモックモード限定。

| URLクエリ | 状態 |
| --- | --- |
| `?elevation=flat` | 全点10mの平坦ルート |
| `?elevation=hill` | 上り下りのあるルート |
| `?elevation=partial` | 中央部分が欠測 |
| `?elevation=missing` | 全点欠測 |
| `?elevation=slow` | 解析前に3秒待機（再検索・中断確認） |
| `?elevation=error` | 解析失敗（解析だけの再試行確認） |

未指定時は坂道許容度「避ける」で平坦、それ以外で起伏を返す。モックには実測ではないことを表示する。

`frontend`で`npm test`、`npm run typecheck`、`npm run build`、ルートで`git diff --check`を実行する。ブラウザでは375px幅とPCで、平坦・起伏・欠測、解析進捗中の詳細開閉とフォーカス、再検索・リセット時の旧結果破棄、解析だけの再試行を確認する。実DEMの検証と実BE結合・実機モバイルの検証は区別する。
